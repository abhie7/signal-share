# SignalShare technical audit (v1.2.4)

Scope: entire repository as of v1.2.4 (Next.js 16 + custom Fastify 5 server, WebRTC data channels,
WebSocket signaling, SSE relay). Every finding below was traced in code; file references are to the
pre-overhaul tree.

## Architecture as found

- One Node process: Fastify serves `/api/ws` (signaling), `/api/transfer/:id/*` (SSE relay) and hands
  everything else to Next.js. All state is in memory (`server/utils/sessions.ts`, `peers.ts`).
- Client: zustand stores + four hooks (`use-websocket`, `use-transfer`, `use-webrtc`, `use-relay`,
  `use-screen-share`) driven by `useEffect` chains reacting to store changes.
- Transport: WebRTC with Google STUN only. "Remote" relay = sender base64-encodes chunks into the
  signaling WebSocket, server re-emits them over SSE.

## What was preserved

Folder drag-and-drop zipping in a worker (`lib/utils/zip*`), IndexedDB history, Fastify + Next
single-process deployment, random device names, sound cues, theme support.

## Fix strategy (implemented)

1. Versioned, validated signaling protocol; sessions carry secret participant tokens so a dropped
   socket can re-attach (`session.resume`) without losing the share; heartbeat both directions.
2. Transport ladder owned by one connection manager: WebRTC (STUN + optional TURN with ephemeral
   credentials) → server WebSocket relay (end-to-end AES-GCM encrypted). Each attempt is bounded and
   its failure reason recorded. Success is declared only after the data path carries a protocol
   round-trip.
3. One transfer protocol for both transports: receiver-driven `ready(file, offset)` (resume),
   windowed acks (backpressure + truthful sender progress), per-chunk SHA-256 folded into a per-file
   digest, receiver-confirmed completion.
4. Screen share rebuilt around an explicit state machine; capture happens inside the click handler,
   media flow is verified via decoded frames, stop is propagated.
5. Server hardening: origin check, token-scoped relaying, rate limits, connection limits, readiness,
   graceful shutdown, structured logs with correlation ids.
6. New UI organised around the four real tasks (send files, send text, share screen, receive).
